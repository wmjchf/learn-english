## 1. 目标与边界

把 PRD 闭环落成可运行系统：

```
词库批次 → 日课生成（场景+短文+对话+回填）→ 点词/朗读/生词
  → SRS + 文章复现回流 → 打卡连胜 → 画像反哺下一篇
```

**本仓库已有**：Flutter App、Express + MySQL、手机号验证码登录 / JWT / 注销。

**本版要新增**：画像与 Onboarding、词库与计划指针、CEFR 测评、日课生成与公共池、阅读与点词、生词状态机、打卡连胜。

**明确不做（对齐 PRD §13.4）**：OCR 上传路径 A、售卖补签、社区、双计划并行、画像改历史数据。

## 4. 领域模型（核心）

### 4.1 用户画像（与 PRD 字段对齐）

挂在 `users` 扩展表 `user_profiles`（一对一）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ability_level` | ENUM A1–C2 | 能力水平，仅测评写入 |
| `generation_level` | ENUM A1–C2 | 文章生成水平基准；首次=测评结果，之后用户 ±1 |
| `job_code` | VARCHAR | 归一化职业码；写入生成 prompt，**不映射词库** |
| `job_raw` | VARCHAR | 用户原文，生成修饰用 |
| `scenes` | JSON | 场景码数组，1–3 |
| `interests` | JSON | 兴趣码数组，1–3（Onboarding 不可空） |
| `daily_minutes` | INT | 预设 chips：10 / 15 / 20 / 30 / 45 / 60；也可由天数反算为其他值 |
| `target_days` | INT | 计划天数（与分钟双向联动结果） |
| `primary_bank_id` | BIGINT | 主词库；MVP 唯一计划指针 |
| `onboarding_step` | VARCHAR | 当前 Onboarding 步骤；`done` 后进主壳 |
| `timezone` | VARCHAR | 默认设备时区，打卡按本地日 |

规则（服务端强制）：

- 重测只更新 `ability_level`（及已知词推算缓存），**禁止**覆盖 `generation_level`。
- 改 `generation_level` 只允许相邻一档，并写审计日志。
- 改职业**不**校验词库、不返回 `WORD_BANK_MISMATCH`（职业与词库无绑定）。
- 兴趣 / 场景 / 职业的**展示选项不写死在客户端**：来自选项目录表，经 catalog API 下发；画像里只存用户选中的 code（及职业原文）。

### 4.1.1 选项目录（兴趣 / 场景 / 职业）

表 `option_catalog`（或拆三张同结构表，MVP 一张即可）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT | 主键 |
| `kind` | ENUM `interest\|scene\|job` | 目录类型 |
| `code` | VARCHAR | 稳定码；写入 `interests` / `scenes` / `job_code` |
| `label` | VARCHAR | 主文案（如「科技」「邮件」） |
| `subtitle` | VARCHAR NULL | 副文案（如「数码 · 互联网」）；可空 |
| `sort` | INT | 展示顺序 |
| `enabled` | BOOL | 软下线；已选用户仍可读历史 code |
| `allow_custom` | BOOL | 仅 `kind=job`：为 true 时点选后可弹自由输入（「其他」） |
| `max_select` | INT NULL | 可空；也可用接口层按 kind 写死：interest/scene=3、job=1 |

约定：

- Onboarding 与画像编辑**共用**同一 catalog；App 缓存短 TTL（如 1h）或启动拉取。
- 后台增删选项不发版；禁用项对新选择不可见，不影响已写入画像的 code。
- UI：双列大块网格；项数随接口变化，多则页内滚动，底部 CTA 吸底。

### 4.2 词库

| 表 | 用途 |
| --- | --- |
| `word_banks` | `type=exam\|business`，标题、封面、总词数；**无** `job_codes` 绑定 |
| `word_bank_entries` | `lemma`、展示形、音标、释义、主题桶 `theme_bucket`、排序 `ord`、CEFR 建议档 |

不做 `job_bank_map`。词状态一律按 **lemma** 统计。入库前 lemmatize（可用 `wink-lemmatizer` / `compromise` 等；不规则表自维护）。

**MVP 必须落库的词库（种子，可不全）**

| code | 展示名 | type | 说明 |
| --- | --- | --- | --- |
| `cet4` | 四级 | exam | 先导入子集即可（如 200–500），不必一次 4500 |
| `cet6` | 六级 | exam | 同上 |
| `kaoyan` | 考研 | exam | 同上 |
| `business` | 商务英语 | business | 通用商务词表；不按外贸/程序员拆库 |

约定：

- 三本考试库 + 至少一本商务英语都要在 `word_banks` 有记录；Onboarding 词库步扁平列出，不按 `job` 排序或主推。
- `word_count` 可用**当前已入库条数**算预估；完整目标规模（如四级 4500）可另存 `target_size` 仅展示「目标规模」，避免子集阶段预估天数虚高或虚低——MVP 优先按已入库数算，文案可写「当前词表 N 词」。
- 后续用 import 脚本追加 entries，不改银行主键；cursor 按 `ord` 继续即可。

### 4.3 用户 × 词

`user_words`（用户词生命周期）：

| 字段 | 说明 |
| --- | --- |
| `user_id`, `lemma` | 唯一键 |
| `status` | `learning` / `vocab` / `consolidating` / `mastered` / `known` |
| `srs_step` | 0–4 对应间隔 1/2/4/7/15 天 |
| `next_review_at` | 下次到期 |
| `pass_count` | 行为检测「复现通过」次数，满 3 → mastered |
| `source_lesson_id` | 首次加入生词本的日课 |
| `bank_id` | 若来自某词库计划 |

状态迁移与 PRD §8.1 一致，后端用单一 `WordLifecycleService` 实现，禁止各处散落改状态。

### 4.4 学习计划与批次

| 表 | 用途 |
| --- | --- |
| `user_plans` | 用户当前计划：`bank_id`、指针 `cursor_ord`、预估天数、已知词推算数 |
| `user_daily_batches` | 某日目标词 lemma 列表 + 复习词列表 |

今日批次装配（P0）：

```
new_words = 从 primary_bank 按 cursor 取满 (10–15 − review_quota)
review_words = 到期 consolidating，最多 2–4，允许 next_review_at ±2 天
溢出到期词 → 闪卡队列，不进文章
```

### 4.5 日课（Lesson）

生成产物不是「一篇散文」，而是 **日课包**（对齐托业语境包结构）：

```json
{
  "day_index": 1,
  "theme": "办公室大搬迁",
  "list_label": "List 1 办公室与设备",
  "scene": {
    "role": "你是公司行政部的一名员工",
    "background": "…",
    "tasks": ["读懂搬迁通知", "听懂报修对话", "完成回填"]
  },
  "article": {
    "title": "The Big Move",
    "zh_lead": "…",
    "en_html": "…", 
    "en_plain": "…"
  },
  "dialog": {
    "title": "Something's Broken",
    "zh_lead": "…",
    "turns": [{ "who": "Tom", "en": "…" }]
  },
  "cloze": [
    { "prompt_zh": "复印机", "answer_lemma": "photocopier", "sentence": "The ________ keeps jamming." }
  ],
  "target_lemmas": ["relocate", "renovation", "…"],
  "review_lemmas": ["shipment"],
  "generation_level": "B1",
  "source": "personalized|pool|cache",
  "pool_matched": false
}
```

英文存储建议：

- `en_tokens` JSON：有序 token 数组 `{ surface, lemma, is_target, is_review }`，App 直接渲染高亮，避免前端二次分词不一致。
- 另存 `en_plain` 供 TTS。

表：

| 表 | 用途 |
| --- | --- |
| `lessons` | 日课正文 JSON、用户、日期、bank、source、校验结果 |
| `lesson_pool` | 公共池：按 `bank_id` + `generation_level` + `scene_codes` 索引 |
| `lesson_gen_jobs` | 异步生成任务队列状态 |
| `generate_quota` | 日额度：`manual_free_used`（手动免费已用，上限 1）+ 付费/会员通道；今日自动篇不走此计数 |

### 4.6 测评

| 表 | 用途 |
| --- | --- |
| `assess_items` | 题干、选项、正确项、CEFR 档、lemma |
| `assess_sessions` | 用户会话：起始档、答题轨迹、收敛结果、估词汇量 |
| `user_known_estimates` | 某词库下「测评已知词」推算缓存 |

收敛规则（与 PRD 一致）：8–12 题；连续 3 题同档正确率 >80% 或 <20% 定档；中途退出按已答估级。

### 4.7 打卡与连胜

| 表 | 用途 |
| --- | --- |
| `user_checkins` | `(user_id, local_date)` 唯一；来源 `lesson` / `review` |
| `user_streaks` | 当前连胜、历史最长、本月冻结已用次数 |

定时：按用户时区，本地日 23:00 未打卡且月冻结 <2 → 自动冻结并记日志；否则连胜归零（保留 longest）。

### 6.2.1 选项目录（后台可配）

兴趣 / 场景 / 职业可选块均由此下发；**客户端禁止写死选项列表**（Demo 种子可作 fallback，正式环境以接口为准）。

| 路径 | 说明 |
| --- | --- |
| `GET /api/catalog/interests` | `{ max_select: 3, items: [{ code, label, subtitle? }] }` |
| `GET /api/catalog/scenes` | 同上，`max_select: 3` |
| `GET /api/catalog/jobs` | `{ max_select: 1, items: [{ code, label, subtitle?, allow_custom? }] }` |

也可合并：`GET /api/catalog?kinds=interest,scene,job`。需登录（兴趣起已鉴权）。管理端增删改（P1 可先 SQL/seed；后台 UI 后补）。

`PATCH /api/profile` / Onboarding 提交时校验：code ∈ 当前 enabled 目录（或曾启用过的历史 code）；interest/scene 数量 1–3；job 单选；`allow_custom` 项可附 `job_raw`。

### 6.3 词库与计划

| 路径 | 说明 |
| --- | --- |
| `GET /api/banks` | 扁平列表：考试词库 + 商务英语（无 job 参数） |
| `GET /api/banks/:id` | 词库详情与词数 |
| `POST /api/plans` | 选定主词库，初始化 cursor 与预估 |
| `GET /api/plans/estimate?bank_id=&minutes=&days=` | 双向联动预览（与 §7 同公式） |
| `GET /api/today` | 今日任务：日课卡、到期复习数、连胜、计划 Day n/N |

预估公式（前后端同口径，抽 `shared` 或后端权威、App 复制常量）：

```
dailyWords = minutes / 8 * 12
days = ceil((bankTotal - knownEstimate) / dailyWords)
minutes = ceil((bankTotal - knownEstimate) / days / 12 * 8)
```

约束：`minutes>45` → `warning=aggressive`；`minutes<5` → `warning=too_short`。

## 7. 生成管线

### 7.1 输入装配

```
Profile(generation_level, scenes, interests, job_raw)
+ Batch(target_words[10-15], review_words[0-4])
+ length_by_minutes
+ coherence_mode=strict
→ Prompt
```

Prompt 必须要求输出 **合法 JSON 日课包**（场景 / 短文中英 / 对话中英 / cloze / 目标词列表），禁止散文外壳。

### 7.2 校验（任一步失败 → 重试，最多 2 次）

| 步 | 实现 |
| --- | --- |
| 覆盖率 | lemma 集合：短文+对话中目标词出现率 ≥ 90%；每词 ≤ 2 |
| 难度 | 非目标词对照 CEFR 词表；越级比例超阈值失败 |
| 结构 | JSON schema：scene/tasks、article、dialog、cloze 齐全 |
| 语法 | 可选二次 LLM「只输出 pass/fail」；失败计一次重试 |

仍失败：从 `lesson_pool` 按 `generation_level + scene + bank` 取一篇，`source=pool`，客户端文案标明「未按今日词表定制」。

### 7.3 冷启动与额度

1. Onboarding 完成：`lesson_pool` 匹配秒出 → 今日可读。
2. 后台 `lesson_gen_jobs` 异步产个性化篇，完成后可替换未读池课或作为明日课。
3. 缓存键：`bank_id + generation_level + scene_hash + target_set_hash`（target 集合规范化排序）。
4. 今日自动篇不扣手动额度；手动生成免费 1 次/日，超出走付费；命中缓存/池不扣额度。

### 7.4 词形与点词

- 服务端维护 `lemma(surface)`；覆盖率、掌握度、生词本主键皆 lemma。
- Lookup：优先日课内嵌 `target` 语境义；否则全局词典表；返回是否 ⭐。

```
  登录成功且 onboarding 未完成 → 兴趣起续做 Onboarding
  登录成功且 onboarding 已完成 → 主壳今日
有 token 且 onboarding_step != done → Onboarding 栈（不可进 Tab）
有 token 且 onboarding_step == done → 主壳今日
```

- 兴趣及之后的写接口须鉴权；未登录不可进今日。
- 主壳：`BottomNav` 四 Tab；日课与复习为全屏路由（无底栏）。
- 登录成功后拉 `/api/profile`（或 `/api/auth/me` 扩展字段）决定跳转。

TTS：

- `LessonTts.speakPlain(en_plain)` / `speakWord(surface)`。
- 点词打断全文：`stop()` → `speakWord`；播完不自动续读全文（MVP）。

点词：英文 token 手势 → 乐观显示本地 token 信息 → 必要时 `lookup` 补词典。

## 12. 观测与风险对策

| 风险 | 工程对策 |
| --- | --- |
| 生成质量 | 校验指标打点；失败率告警；池降级必带 `source` |
| 首课等待 | Onboarding 只走池匹配；个性化异步 |
| 成本 | 额度 + 缓存键；池命中不计费 |
| lemma 错误 | 单测不规则表；覆盖率单测用固定课文 |
| 时区打卡 | 服务端用 profile.timezone 算 local_date，禁止纯 UTC 日切 |

## 13. 测试要点

- 计划公式单测：与 PRD 示例（4500/2000/20min ≈ 84 天）一致。
- 状态机单测：认识直达 mastered；答错重置 srs_step。
- 测评：中途 finish 仍写出 ability_level。
- 重测：generation_level 不变。
- 生成校验：缺目标词 → retry → pool。
- 日课 JSON schema 校验。

## 14. 与内容包的衔接

运营/教研产出的 HTML（如 Day1–5）需转换脚本：

1. 解析 `.intro` / `.zhlead` / `.article` / `.dialog` / `.recall`。
2. 分词 + mark → `en_tokens` + `target_lemmas`。
3. 写入 `lesson_pool`，打上 bank/level/scene 标签。

脚本可放 `backend/scripts/import-lesson-html.js`（实现阶段再加）。
